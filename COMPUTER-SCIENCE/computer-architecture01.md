# 컴퓨터 구조

## 1. 컴퓨터 구조란?

컴퓨터가 **정보를 어떻게 저장하고, 이동시키고, 처리하는지**를 이해하는 것

컴퓨터가 이해하고 처리하는 정보는 크게 두 가지

* **데이터(Data)** : 계산하거나 처리할 대상
* **명령어(Instruction)** : 데이터를 어떻게 처리할지 나타내는 명령

예를 들어

```text
10 + 20
```

에서

* `10`, `20` → 데이터
* `+` → 연산을 수행하라는 명령

---

# 2. 컴퓨터의 주요 구성 요소

컴퓨터를 크게 나누면 다음과 같다.

```text
CPU
RAM
SSD
입출력 장치
```

## CPU

CPU는 **명령어를 실행하고 데이터를 처리**한다.

CPU의 주요 구성 요소

```text
CPU
 ├── ALU (산술논리연산장치)
 ├── 제어장치 (Control Unit)
 └── 레지스터 (Register)
```

### ALU

실제 계산과 논리 연산을 수행한다.

```text
10 + 20
10 - 20
10 × 20
10 > 20
```

등의 연산을 수행한다.

### 제어장치

명령어를 해석하고 CPU의 각 구성 요소가 **언제 무엇을 해야 하는지 제어 신호를 생성**한다.

예를 들어

```text
메모리에서 명령어 가져와!
메모리에서 데이터 읽어와!
ALU에서 더하기 수행해!
계산 결과를 레지스터에 저장해!
```

와 같은 동작을 제어한다.

### 레지스터

CPU 내부에 있는 **작은 저장 공간**이다.

CPU가 계산에 사용할 데이터나 계산 결과 등을 임시로 저장한다.

```text
RAM → 레지스터 → ALU
```

RAM보다 CPU 내부의 레지스터를 사용하는 것이 일반적으로 더 빠르기 때문에 CPU는 연산에 필요한 값을 레지스터에 가져와 사용한다.

비유하면

```text
RAM       = 창고
레지스터 = 작업대
ALU       = 계산기
```

창고에 있는 물건을 작업대로 가져온 뒤 계산하는 것과 비슷하다.

---

# 3. PC와 IR

CPU에는 여러 종류의 레지스터가 존재한다.

그중 명령어 실행 과정에서 중요한 것이

```text
PC (Program Counter)
IR (Instruction Register)
```

이다.

## PC

**다음에 실행할 명령어가 저장된 메모리 주소**를 저장한다.

예를 들어

```text
PC = 1000
```

이라면

```text
메모리 주소 1000번에 있는 명령어를 가져와 실행할 차례
```

라는 의미이다.

## IR

CPU가 메모리에서 가져온 **현재 실행할 명령어**를 저장한다.

예를 들어

```text
메모리
1000 → 덧셈 명령어
```

라면 CPU가 1000번지의 명령어를 가져온 후

```text
IR → 덧셈 명령어
```

처럼 저장한다.

제어장치는 IR에 저장된 명령어를 해석하여 어떤 작업을 해야 하는지 결정한다.

---

# 4. RAM과 SSD

## RAM

현재 실행 중인 프로그램과 필요한 데이터를 저장한다.

특징

* CPU가 빠르게 접근할 수 있다.
* 전원이 꺼지면 일반적으로 데이터가 사라진다.
* 휘발성 메모리

## SSD

프로그램이나 파일 등을 **장기간 저장**한다.

특징

* 전원이 꺼져도 데이터가 유지된다.
* 비휘발성 저장장치

프로그램 실행을 단순화하면

```text
SSD
 ↓
RAM
 ↓
CPU가 필요한 명령어와 데이터를 가져옴
 ↓
레지스터
 ↓
ALU에서 연산
```

라고 볼 수 있다.

단, 실제 CPU 내부의 동작은 이보다 훨씬 복잡하며 모든 데이터가 반드시 똑같은 순서로 이동한다고 생각하면 안 된다.

---

# 5. 메인보드와 시스템 버스

CPU, RAM 등의 컴퓨터 구성 요소는 **시스템 버스(System Bus)**를 통해 정보를 주고받는다.

시스템 버스는 크게 세 가지로 나눌 수 있다.

```text
주소 버스
데이터 버스
제어 버스
```

## 주소 버스

**어느 위치에 접근할 것인지** 나타내는 주소를 전달한다.

```text
CPU → 주소 버스 → 메모리
```

예:

```text
1000
```

## 데이터 버스

실제 **데이터나 명령어**를 전달한다.

```text
메모리 → 데이터 버스 → CPU
```

예:

```text
10
20
덧셈 명령어
```

## 제어 버스

읽기/쓰기와 같은 **제어 신호**를 전달한다.

예:

```text
READ
WRITE
```

---

# 6. CPU가 메모리에서 명령어를 가져오는 과정

예를 들어 다음과 같은 프로그램이 있다고 생각한다.

```text
10 + 20
```

메모리에 단순화해서 다음과 같이 저장되어 있다고 가정한다.

```text
메모리 주소       저장된 내용

1000              덧셈 명령어
1001              10
1002              20
```

이것은 **메모리 주소와 그 주소에 저장된 값을 표현한 것**이다.

`1000 → 덧셈 명령어` 자체가 간접 주소 지정 방식이라는 의미는 아니다.

---

## ① PC가 다음 명령어의 주소를 가지고 있음

```text
PC = 1000
```

PC에는 다음에 실행할 명령어의 주소가 들어 있다.

---

## ② 주소 버스를 통해 주소 전달

CPU는 PC에 저장된 `1000`을 이용하여 메모리의 1000번지에 접근한다.

```text
PC
 ↓
1000
 ↓
주소 버스
 ↓
메모리 1000번지
```

---

## ③ 제어장치가 메모리 읽기 신호를 보냄

제어장치는 메모리에

```text
READ
```

라는 읽기 제어 신호를 보낸다.

```text
제어장치
   ↓
READ 신호
   ↓
제어 버스
   ↓
메모리
```

즉,

```text
주소 버스 → "1000번지에 접근해!"
제어 버스 → "그 내용을 읽어!"
```

라고 생각하면 된다.

---

## ④ 메모리가 명령어를 데이터 버스로 전달

메모리 1000번지에는

```text
덧셈 명령어
```

가 저장되어 있으므로 메모리가 해당 명령어를 CPU로 전달한다.

```text
메모리
  ↓
덧셈 명령어
  ↓
데이터 버스
  ↓
CPU
```

CPU는 가져온 명령어를 **IR(명령어 레지스터)**에 저장한다.

```text
IR = 덧셈 명령어
```

---

## ⑤ 제어장치가 명령어 해석

제어장치는 IR에 저장된 명령어를 해석한다.

예를 들어 개념적으로

```text
더하기 10 20
```

이라는 명령이라면

```text
무엇을 할 것인가?
→ 더하기

어떤 데이터를 사용할 것인가?
→ 10, 20
```

을 파악한다.

실제 CPU의 명령어 형식은 이보다 훨씬 구체적이지만, 학습 단계에서는 이런 형태로 이해하면 된다.

---

# 7. 10 + 20 계산 과정

이제 실제 계산 과정을 단순화해서 보면

```text
10 + 20
```

을 계산하기 위해 CPU가 필요한 데이터를 가져온다.

## ① 10을 메모리에서 가져옴

```text
주소 버스
   ↓
1001
   ↓
메모리

제어 버스
   ↓
READ

메모리
   ↓
10
   ↓
데이터 버스
   ↓
R1
```

결과

```text
R1 = 10
```

---

## ② 20을 메모리에서 가져옴

```text
주소 버스
   ↓
1002
   ↓
메모리

제어 버스
   ↓
READ

메모리
   ↓
20
   ↓
데이터 버스
   ↓
R2
```

결과

```text
R2 = 20
```

---

## ③ ALU에서 계산

제어장치가 ALU에게 덧셈을 수행하도록 제어한다.

```text
R1 = 10
R2 = 20

   ↓

ALU

10 + 20

   ↓

30
```

결과를 레지스터에 저장한다.

```text
R3 = 30
```

---

## ④ 필요하면 메모리에 결과 저장

계산 결과를 메모리에 저장해야 한다면 제어장치가 **WRITE 신호**를 보낸다.

```text
CPU
 ↓
WRITE 신호
 ↓
제어 버스
 ↓
메모리
```

그리고

```text
주소 버스 → 저장할 메모리 주소
데이터 버스 → 30
제어 버스 → WRITE
```

를 이용하여 메모리에 `30`을 저장한다.

---

# 8. 전체적인 흐름

`10 + 20`을 계산하는 과정을 단순화하면

```text
[SSD]
 프로그램 저장
    ↓
[RAM]
 프로그램과 필요한 데이터 저장
    ↓
[PC]
 다음에 실행할 명령어의 주소 확인
    ↓
[주소 버스]
 메모리 주소 전달
    ↓
[제어 버스]
 READ 신호 전달
    ↓
[메모리]
 명령어 전달
    ↓
[데이터 버스]
 명령어 전달
    ↓
[IR]
 현재 실행할 명령어 저장
    ↓
[제어장치]
 명령어 해석
    ↓
[레지스터]
 필요한 데이터 저장
    ↓
[ALU]
 10 + 20 계산
    ↓
[레지스터]
 결과 30 저장
    ↓
필요하다면
    ↓
[메모리]
 결과 저장
```

핵심은 다음과 같다.

```text
PC
→ 다음 명령어의 주소

IR
→ 현재 가져온 명령어

제어장치
→ 명령어를 해석하고 제어 신호를 생성

레지스터
→ CPU가 사용할 데이터와 중간 결과를 빠르게 저장

ALU
→ 실제 연산 수행
```

# 9. 소스 코드와 기계어

사람이 작성하는 프로그램은 일반적으로 사람이 이해하기 쉬운 형태로 작성한다.

```text
10 + 20
```

컴퓨터가 직접 실행하는 것은 **기계어(Machine Language)**이다.

컴퓨터가 이해하는 명령은 결국 0과 1로 표현된다.

```text
소스 코드
   ↓
컴파일 / 해석 등의 과정
   ↓
컴퓨터가 실행할 수 있는 형태
   ↓
CPU가 명령어 실행
```

---

# 10. 고급 언어와 저급 언어

## 고급 언어

사람이 이해하기 쉬운 언어

예:

```text
Java
Python
C
```

## 저급 언어

컴퓨터에 가까운 언어

대표적으로

```text
어셈블리어
```

가 있다.

최종적으로 CPU가 직접 실행하는 것은 해당 CPU가 이해할 수 있는 **기계어 명령어**이다.

---

# 11. 컴파일과 인터프리트

## 컴파일

프로그램을 실행하기 전에 소스 코드를 다른 실행 가능한 형태로 변환하는 과정.

개념적으로

```text
소스 코드
 ↓
컴파일러
 ↓
변환된 코드
 ↓
실행
```

## 인터프리트

프로그램 실행 과정에서 코드를 해석하여 실행하는 방식.

단, 현대 언어의 실행 방식은 단순히

```text
컴파일 언어 = 컴파일
인터프리터 언어 = 한 줄씩 실행
```

으로 완전히 나누기는 어렵다.

예를 들어 Java는

```text
Java 소스 코드
 ↓
컴파일
 ↓
바이트코드
 ↓
JVM
 ↓
실행
```

과 같은 과정을 거친다.

---

# 12. 명령어의 기본 구조

명령어는 개념적으로 다음과 같이 볼 수 있다.

```text
명령어 = 연산 코드 + 피연산자

Opcode    +    Operand
```

## Opcode

**무슨 작업을 할 것인지** 나타낸다.

예:

```text
ADD
SUB
LOAD
STORE
```

## Operand

연산에 사용할 **데이터 또는 데이터가 있는 위치**를 나타낸다.

예:

```text
ADD R1, R2
```

라면

```text
ADD → 어떤 연산?
      덧셈

R1, R2 → 어떤 데이터를 사용할 것인가?
```

라고 이해할 수 있다.

실제 명령어마다 피연산자의 개수와 형태는 다를 수 있다.

---

# 13. 유효 주소 (Effective Address)

메모리에 있는 실제 데이터를 찾아가기 위해 사용되는 **실제 메모리 주소**를 유효 주소라고 한다.

주소 지정 방식에 따라 피연산자가 의미하는 것이 달라질 수 있다.

---

# 14. 주소 지정 방식

## ① 즉시 주소 지정 (Immediate Addressing)

피연산자에 **데이터 자체**가 들어 있다.

```text
ADD 10
```

개념적으로

```text
Operand = 10
```

이다.

즉,

```text
피연산자 → 데이터 그 자체
```

이므로 데이터를 가져오기 위해 별도의 메모리 주소를 찾아갈 필요가 없다.

장점:

* 빠른 접근

단점:

* 명령어의 피연산자 영역 크기 때문에 표현할 수 있는 데이터 크기에 제한이 있다.

---

## ② 직접 주소 지정 (Direct Addressing)

피연산자가 **데이터가 저장된 메모리 주소**를 가지고 있다.

```text
Operand = 1000
```

그리고

```text
메모리 1000번지 → 50
```

이라면

```text
명령어
  ↓
1000
  ↓
메모리 1000번지
  ↓
50
```

즉,

```text
Operand → 유효 주소
```

이다.

---

## ③ 간접 주소 지정 (Indirect Addressing)

피연산자가 **유효 주소가 저장되어 있는 메모리 주소**를 가지고 있다.

예를 들어

```text
명령어의 Operand = 1BA5
```

이고

```text
메모리 1BA5 → 1HA2
메모리 1HA2 → 실제 데이터
```

라면

```text
Operand
  ↓
1BA5
  ↓
메모리 1BA5
  ↓
1HA2
  ↓
메모리 1HA2
  ↓
실제 데이터
```

즉,

```text
Operand
 ↓
유효 주소가 저장된 주소
 ↓
유효 주소
 ↓
실제 데이터
```

가 된다.

따라서 직접 주소 지정에 비해 **메모리에 한 번 더 접근**해야 한다.

---

## ④ 레지스터 주소 지정 (Register Addressing)

피연산자가 **데이터를 저장하고 있는 레지스터를 지정**한다.

예:

```text
ADD R1
```

```text
R1 = 10
```

이라면

```text
Operand
 ↓
R1
 ↓
10
```

이다.

---

## ⑤ 레지스터 간접 주소 지정 (Register Indirect Addressing)

피연산자가 지정한 레지스터에 **메모리 주소**가 들어 있다.

예:

```text
R1 = 1000
```

그리고

```text
메모리 1000번지 → 50
```

이라면

```text
Operand
 ↓
R1
 ↓
1000
 ↓
메모리 1000번지
 ↓
50
```

즉,

```text
레지스터 → 메모리 주소 → 실제 데이터
```

의 형태이다.

---

# 15. 주소 지정 방식 비교

| 방식            | Operand가 의미하는 것   |
| ------------- | ----------------- |
| 즉시 주소 지정      | 데이터 자체            |
| 직접 주소 지정      | 데이터가 저장된 메모리 주소   |
| 간접 주소 지정      | 유효 주소가 저장된 메모리 주소 |
| 레지스터 주소 지정    | 데이터가 저장된 레지스터     |
| 레지스터 간접 주소 지정 | 메모리 주소가 저장된 레지스터  |

핵심 차이:

```text
즉시
→ Operand 자체가 데이터

직접
→ Operand = 데이터의 메모리 주소

간접
→ Operand = 유효 주소가 저장된 메모리 주소

레지스터
→ Operand = 데이터가 있는 레지스터

레지스터 간접
→ Operand = 메모리 주소가 있는 레지스터
```

# 16. 핵심 정리

```text
CPU
 ├── ALU
 │    └── 실제 연산
 │
 ├── 제어장치
 │    └── 명령어 해석 + 제어 신호 생성
 │
 └── 레지스터
      └── 데이터 / 명령어 / 중간 결과 저장
```

명령어 실행의 핵심 레지스터:

```text
PC
→ 다음에 실행할 명령어의 주소

IR
→ 현재 실행할 명령어
```

시스템 버스:

```text
주소 버스
→ 어디에 접근할지

데이터 버스
→ 무엇을 전달할지

제어 버스
→ 어떤 동작을 할지
```

CPU의 기본적인 동작:

```text
PC
 ↓
명령어 주소 확인
 ↓
메모리 READ
 ↓
명령어 가져오기
 ↓
IR에 저장
 ↓
제어장치가 해석
 ↓
필요한 데이터 가져오기
 ↓
레지스터에 저장
 ↓
ALU에서 연산
 ↓
결과를 레지스터에 저장
 ↓
필요하면 메모리에 WRITE
```

주소 지정 방식은 **명령어의 Operand가 데이터를 어떻게 가리키는지**에 따라 구분한다.

```text
즉시     → 데이터 자체
직접     → 데이터의 주소
간접     → 주소가 저장된 주소
레지스터 → 데이터가 있는 레지스터
레지스터 간접 → 주소가 있는 레지스터
```
