# 트랜잭션 제어와 세션

## 1. 트랜잭션(Transaction)이란?

트랜잭션(Transaction)은 **하나의 단위로 데이터를 처리하는 작업 단위**이다.

쉽게 말하면,

> 데이터베이스에서 하나의 작업을 완전히 처리하기 위해 묶어 놓은 SQL문들의 집합

이다.

트랜잭션은 더 이상 분해할 수 없는 **논리적인 작업 단위**이며, 하나의 작업 또는 서로 밀접하게 연관된 작업을 수행하기 위해 하나 이상의 DML 명령어로 이루어진다.

---

## 2. 트랜잭션이 필요한 이유

예를 들어 A 계좌에 100만 원이 있고 B 계좌에는 0원이 있다고 가정한다.

A 계좌에서 B 계좌로 100만 원을 이체하려면 다음과 같이 두 번의 `UPDATE`가 필요하다.

```sql
-- (1) A 계좌에서 100만 원 차감
UPDATE ACCOUNT
SET BALANCE = 0
WHERE ACCNO = 'A';

-- (2) B 계좌에 100만 원 추가
UPDATE ACCOUNT
SET BALANCE = 1000000
WHERE ACCNO = 'B';
```

정상적으로 두 SQL문이 모두 실행되면 다음과 같다.

| 계좌 | 변경 |
|---|---:|
| A 계좌 | 100만 원 → 0원 |
| B 계좌 | 0원 → 100만 원 |

### 문제 상황

만약 (1)번 SQL문을 실행한 후 데이터베이스에 문제가 발생하여 (2)번 SQL문을 실행하지 못한다면?

| 계좌 | 결과 |
|---|---:|
| A 계좌 | 0원 |
| B 계좌 | 0원 |

A 계좌에서는 돈이 빠져나갔지만 B 계좌에는 돈이 들어오지 않는 문제가 발생한다.

즉, 하나의 작업이 중간까지만 실행된 상태가 되어 **데이터의 무결성이 깨질 수 있다.**

---

## 3. 트랜잭션의 필요성

이러한 문제를 해결하기 위해 **트랜잭션**을 사용한다.

트랜잭션에서는 하나의 작업이 다음 두 가지 결과 중 하나가 되도록 한다.

### ① 모든 작업이 정상적으로 완료

- A 계좌: -100만 원
- B 계좌: +100만 원

→ 모든 작업이 정상적으로 완료되면 `COMMIT`

### ② 작업 중 문제가 발생

- A 계좌: -100만 원
- B 계좌: 변경되지 않음

→ 문제가 발생하면 `ROLLBACK`하여 작업을 취소

즉,

> 트랜잭션은 여러 SQL문을 하나의 작업 단위로 묶어 전체 작업이 정상적으로 처리되거나, 문제가 발생하면 변경 사항을 취소할 수 있도록 한다.

---

## 4. 트랜잭션 제어 명령어

트랜잭션을 제어하는 대표적인 명령어는 다음과 같다.

| 명령어 | 설명 |
|---|---|
| `COMMIT` | 변경 사항을 확정하고 영구적으로 반영 |
| `ROLLBACK` | 변경 사항을 취소하고 이전 상태로 되돌림 |
| `SAVEPOINT` | 트랜잭션 중간에 되돌아갈 지점을 지정 |

---

## 5. COMMIT

`COMMIT`은 현재 트랜잭션에서 수행한 변경 사항을 **영구적으로 반영**한다.

```sql
UPDATE ACCOUNT
SET BALANCE = 0
WHERE ACCNO = 'A';

COMMIT;
```

`COMMIT`을 실행하면 변경 사항이 확정된다.

따라서 일반적으로

> **COMMIT한 변경 사항은 ROLLBACK으로 되돌릴 수 없다.**

---

## 6. ROLLBACK

`ROLLBACK`은 현재 트랜잭션에서 수행한 변경 사항을 취소한다.

```sql
UPDATE ACCOUNT
SET BALANCE = 0
WHERE ACCNO = 'A';

ROLLBACK;
```

위와 같이 실행하면 `UPDATE`로 변경한 내용이 취소된다.

### COMMIT과 ROLLBACK

```text
UPDATE
  ↓
변경 사항 발생
  ↓
┌─────────────┐
│             │
COMMIT      ROLLBACK
│             │
↓             ↓
변경 확정     변경 취소
```

따라서 **COMMIT하기 전에는 ROLLBACK을 통해 변경 사항을 취소할 수 있다.**

---

## 7. SAVEPOINT

트랜잭션 작업 중간에 특정 지점을 지정하고 싶다면 `SAVEPOINT`를 사용한다.

```sql
UPDATE ACCOUNT
SET BALANCE = BALANCE - 100
WHERE ACCNO = 'A';

SAVEPOINT SP1;

UPDATE ACCOUNT
SET BALANCE = BALANCE + 100
WHERE ACCNO = 'B';
```

이후 문제가 발생했을 때

```sql
ROLLBACK TO SP1;
```

을 실행하면 **SAVEPOINT 이후의 작업만 취소**할 수 있다.

```text
UPDATE A
   ↓
SAVEPOINT SP1
   ↓
UPDATE B
   ↓
ROLLBACK TO SP1
   ↓
UPDATE B 취소
UPDATE A 유지
```

### ROLLBACK과 SAVEPOINT의 차이

| 명령어 | 동작 |
|---|---|
| `ROLLBACK` | 현재 트랜잭션의 변경 사항을 전체 취소 |
| `ROLLBACK TO SAVEPOINT` | 지정한 `SAVEPOINT` 이후의 작업만 취소 |

---

## 8. 트랜잭션 진행 과정

트랜잭션은 다음과 같은 과정으로 진행된다.

```text
DML 실행
   ↓
트랜잭션 시작
   ↓
추가 작업
   ↓
트랜잭션 진행
   ↓
┌───────────────┐
│               │
COMMIT       ROLLBACK
│               │
↓               ↓
변경 확정       변경 취소
```

예를 들어 계좌이체라면 다음과 같다.

```text
UPDATE A 계좌
      ↓
UPDATE B 계좌
      ↓
작업 정상 완료?
   ↙       ↘
 YES        NO
  ↓          ↓
COMMIT     ROLLBACK
  ↓          ↓
변경 확정    변경 취소
```

## 9. 세션(Session)이란?

세션(Session)은 **데이터베이스에 접속하여 작업을 수행하는 하나의 연결 단위**이다.

오라클에서 세션은

> 데이터베이스 접속을 시작하고 여러 데이터베이스 작업을 수행한 후 접속을 종료하기까지의 전체 기간

을 의미한다.

예를 들어 SQL*Plus 또는 SQL Developer 등을 통해 데이터베이스에 접속하면 하나의 세션이 생성된다.

```text
데이터베이스 접속
      ↓
세션 시작
      ↓
SQL 실행
      ↓
COMMIT
      ↓
SQL 실행
      ↓
ROLLBACK
      ↓
SQL 실행
      ↓
데이터베이스 접속 종료
      ↓
세션 종료
```

---

## 10. 세션과 트랜잭션의 관계

하나의 세션에서는 여러 개의 트랜잭션이 발생할 수 있다.

```text
세션
 ├── 트랜잭션 1
 │    ├── DML
 │    ├── DML
 │    └── COMMIT
 │
 ├── 트랜잭션 2
 │    ├── DML
 │    └── ROLLBACK
 │
 └── 트랜잭션 3
      ├── DML
      └── COMMIT
```

따라서 개념적으로

> **세션 > 트랜잭션**

관계로 이해하면 된다.

| 개념 | 의미 |
|---|---|
| 세션 | 데이터베이스에 접속해 있는 전체 기간 |
| 트랜잭션 | 세션 안에서 수행되는 하나의 작업 단위 |

---

## 11. 읽기 일관성(Read Consistency)

오라클에서는 여러 세션이 동시에 같은 데이터를 사용할 수 있다.

이때 중요한 개념이 **읽기 일관성(Read Consistency)**이다.

예를 들어 세션 A가 데이터를 수정했다고 하자.

```sql
UPDATE ACCOUNT
SET BALANCE = 0
WHERE ACCNO = 'A';
```

하지만 아직 `COMMIT`하지 않았다.

이 상태에서 세션 B가 같은 데이터를 조회하면 세션 A의 **아직 확정되지 않은 변경 내용을 그대로 보지 않는다.**

```text
세션 A                     세션 B

UPDATE
BALANCE = 0
   ↓
COMMIT하지 않음
   │
   │                    SELECT
   │                       ↓
   └────────────────→ 확정된 데이터 조회
```

즉,

> 다른 세션에서 아직 COMMIT되지 않은 변경 내용을 함부로 읽지 않도록 하여 데이터의 일관성을 유지한다.

---

## 12. LOCK(잠금)

한 세션이 데이터를 변경하는 동안 다른 세션이 같은 데이터를 동시에 변경하면 문제가 발생할 수 있다.

이를 방지하기 위해 데이터베이스에서는 **LOCK(잠금)**을 사용한다.

LOCK은 쉽게 말하면,

> 한 세션이 조작 중인 데이터를 다른 세션이 동시에 변경하지 못하도록 접근을 제한하는 것

이다.

예를 들어 세션 A가 다음 SQL을 실행했다고 하자.

```sql
UPDATE ACCOUNT
SET BALANCE = 0
WHERE ACCNO = 'A';
```

아직 `COMMIT`하지 않은 상태라면 해당 데이터에 잠금이 발생한다.

이때 세션 B가 같은 데이터를 변경하려고 하면 바로 실행되지 않고 기다리게 된다.

```text
세션 A                         세션 B

UPDATE
ACCOUNT
   ↓
LOCK 발생
   │
   │                       UPDATE
   │                          ↓
   │                    LOCK 때문에 대기
   │                          ↓
   │                     작업 대기
   │
COMMIT
   ↓
LOCK 해제
   ↓
                         UPDATE 실행
```

---

## 13. HANG

세션 B가 세션 A의 LOCK이 해제될 때까지 작업을 기다리는 상황을 일반적으로 **HANG**이라고 표현할 수 있다.

예를 들어,

```text
세션 A

UPDATE 실행
    ↓
LOCK 발생
    ↓
COMMIT하지 않음


세션 B

UPDATE 실행
    ↓
세션 A가 해당 데이터를 사용 중
    ↓
작업 대기
    ↓
HANG
```

세션 A가

```sql
COMMIT;
```

또는

```sql
ROLLBACK;
```

을 실행하면 트랜잭션이 종료되고 관련 LOCK이 해제된다.

그 후 세션 B가 작업을 진행할 수 있다.

---

## 14. COMMIT / ROLLBACK / LOCK의 관계

세 가지 개념을 연결해서 이해하는 것이 중요하다.

```text
DML 실행
   ↓
데이터 변경
   ↓
LOCK 발생
   ↓
COMMIT 전
   ↓
다른 세션에서 같은 데이터 변경 시
대기할 수 있음
   ↓
┌───────────────┐
│               │
COMMIT       ROLLBACK
│               │
↓               ↓
변경 확정       변경 취소
│               │
└───────┬───────┘
        ↓
     LOCK 해제
```

---

## 15. 전체 개념 정리

| 개념 | 의미 |
|---|---|
| 트랜잭션 | 하나의 작업 단위 |
| `COMMIT` | 변경 사항 확정 |
| `ROLLBACK` | 변경 사항 취소 |
| `SAVEPOINT` | 트랜잭션 중간에 되돌아갈 지점 |
| 세션 | DB 접속부터 종료까지의 연결 단위 |
| 읽기 일관성 | 다른 세션의 미확정 변경 내용을 함부로 읽지 않도록 하는 것 |
| LOCK | 다른 세션의 동시 변경을 제한하는 잠금 |
| HANG | LOCK 등으로 인해 다른 세션의 작업이 대기하는 상황 |

---

## 16. 핵심 관계

```text
                    세션
                     │
          ┌──────────┴──────────┐
          │                     │
      트랜잭션 1             트랜잭션 2
          │                     │
        DML                   DML
          │                     │
        LOCK                  LOCK
          │                     │
     ┌────┴────┐          ┌────┴────┐
     │         │          │         │
  COMMIT    ROLLBACK   COMMIT    ROLLBACK
     │         │          │         │
  변경 확정   변경 취소   변경 확정   변경 취소
```

---

## 한 문장으로 정리

> **세션 안에서 트랜잭션 단위로 DML을 수행하고, COMMIT으로 변경을 확정하거나 ROLLBACK으로 취소하며, 변경 중인 데이터는 LOCK을 통해 다른 세션의 동시 변경을 제한하여 데이터의 일관성을 유지한다.**
